## 1. Противоречия в требованиях

1. **Стриминг «по токенам» не сходится с «UI читает только из БД» и записью в БД 2 раза в секунду.** Если соблюдать все три правила, текст будет появляться кусками раз в 500 мс.
   **Правка:** в «Решения» добавить исключение. `ChatService` отдаёт черновик текущего ответа как поток в памяти, ViewModel показывает его поверх сообщения из БД, пока у того статус `streaming`. В БД по-прежнему пишем 2 раза в секунду и в конце. Сформулировать это и в `CLAUDE.md`, иначе агент упрётся в «не отступать от архитектуры».
2. **Офлайн-режим: `pending` (п. 1) или ответ через Foundation Models (п. 6)?** Нужно правило. Предлагаю: без сети всегда `pending`. Если на iOS 26 доступна модель, в сообщении появляется кнопка «Ответить офлайн». Автоматически офлайн-моделью не отвечаем.
3. **У сообщений пользователя и ассистента одна цепочка статусов, хотя состояния у них разные.** У пользователя это `pending` → `sent`, у ассистента `streaming` → `done`/`cancelled`/`failed`/`interrupted`. Статуса `sent` в модели нет. Надо описать два автомата состояний и уточнить, на каком сообщении висят `errorKind` и «Повторить». Предлагаю: на ответе ассистента, а повтор переиспользует тот же ответ.
4. **Неясно, что считать состоянием «загрузка».** Локальная БД загружается мгновенно. Предлагаю считать загрузкой ожидание первого токена: показывать индикатор «печатает…».
5. **Неясно, какую историю отправлять в LLM.** Предлагаю: системный промпт «отвечай по-русски», последние N сообщений со статусом `done` (обрезка по символам), без `failed`/`cancelled`. От этого зависит, хватит ли лимита Groq на проверку.
6. **Автозаголовок (3.3).** Зафиксировать, что заголовок берётся обрезкой первого сообщения, а не отдельным запросом к LLM: так не тратится лимит.

## 2. Технические ошибки в текущих файлах

7. **`Package.resolved` фактически не коммитится.** XcodeGen кладёт его внутрь `AIChat.xcodeproj/…/swiftpm/`, а `*.xcodeproj` в игноре, поэтому комментарий в `.gitignore` ничего не даёт. **Правка:** в `project.yml` указать `exactVersion` для GRDB.
8. **`Build.command` ждёт нажатия клавиши (`read -n 1`).** Агент не сможет проверить шаг 0.1: команда повиснет. **Правка:** добавить переменную окружения вроде `NO_PAUSE=1` и использовать её в CLAUDE.md.
9. **Секреты (0.3).** Агент не может и не должен запускать `gen_secrets.py`, а без `Secrets.generated.swift` проект не соберётся. **Правка:** в плане пометить 0.3 как ручной шаг пользователя. До этого собирать с заглушкой, которая выдаёт ошибку «ключ не задан» (это ошибка `unauthorized`). Добавить проверку перед коммитом: `git grep "gsk_"` должен быть пустым.
10. **Маппинг «`URLError` → offline» слишком грубый.** `URLError.cancelled` при нажатии «Стоп» станет «нет сети». **Правка:**
    - offline только для `notConnectedToInternet`, `networkConnectionLost`, `dataNotAllowed`, `timedOut`;
    - `CancellationError` и `.cancelled` дают статус `cancelled`;
    - при HTTP-ошибке дочитать тело ответа, а ошибку внутри SSE (`data: {"error":…}` при статусе 200) тоже маппить;
    - добавить 403: вероятно, нужен отдельный `ErrorKind` (см. п. 13).
11. **`AsyncBytes.lines` пропускает пустые строки.** Тесты парсера на пустые строки будут проверять код, который в продакшене не выполняется. Либо парсить байты самим, либо прямо написать в 2.2, что парсер работает построчно и разделитель событий не нужен.
12. **Тестовая команда в CLAUDE.md указывает `iPhone 16`.** В Xcode 26 по умолчанию стоят симуляторы iPhone 17, так что команда может упасть. Лучше выбирать устройство через `simctl` или явно указать `name=…,OS=…`.

## 3. Риски iOS 18 vs 26

13. **Модель и регион Groq не выбраны.** Нужен шаг **2.0**: выбрать модель, записать лимиты RPM/TPD в «Решения» и проверить доступность из страны проверяющего. Я не проверял, но у Groq могут быть гео-ограничения, и тогда пользователь получит 403. На этот случай нужен понятный текст ошибки.
14. **Foundation Models (6.1):**
    - на симуляторе модель доступна только если на Mac включён Apple Intelligence;
    - русский, насколько я знаю, не входит в языки Apple Intelligence, это нужно проверить до начала работы, иначе бонус бесполезен;
    - всегда обрабатывать `SystemLanguageModel.default.availability`.
15. **Liquid Glass.** При сборке на SDK 26 iOS 26 автоматически меняет внешний вид навбаров и тулбаров. Свой фон у поля ввода будет выглядеть по-разному на 18 и 26. Нужно правило: не использовать `.glassEffect` без `#available`, а в 4.2/4.6 смотреть скриншоты на обеих версиях.
16. **Рантайм iOS 18 для симулятора не входит в Xcode 26.** Его скачивание занимает несколько гигабайт и время. **Правка:** перенести установку в шаг 0, а не в 5.1.
17. **`AttributedString(markdown:)`:**
    - по умолчанию теряет переводы строк, а списки и блоки кода не отрисовываются;
    - на полуготовом markdown во время стриминга возможны артефакты.

    Зафиксировать `.inlineOnlyPreservingWhitespace` и сознательно отказаться от блочной разметки (это пойдёт в «Не сделано»).

**Лимиты бесплатного тарифа** (документация Groq на 08.10.2026):

| Модель | Запросов/мин | Запросов/день | Токенов/мин | Токенов/день |
|---|---|---|---|---|
| `openai/gpt-oss-120b` | 30 | 1 000 | 8 000 | 200 000 |
| `openai/gpt-oss-20b` | 30 | 1 000 | 8 000 | 200 000 |

**Почему эта модель:**
- Обе модели Llama (`llama-3.3-70b-versatile`, `llama-3.1-8b-instant`) отключены для бесплатного тарифа с 16.08.2026.
- Qwen есть только в статусе preview, и одну его версию уже отключили 14.09.2026.
- Из оставшихся production-моделей `gpt-oss-120b` лучше всех справится с русским. `gpt-oss-20b` записал запасной: лимиты у неё те же, но считаются отдельно для каждой модели.

**Что ещё вписал в решения:**
- **Параметры запроса:** `reasoning_effort: "low"`, `include_reasoning: false`, `max_completion_tokens: 1024`. gpt-oss — рассуждающая модель. Без `include_reasoning: false` рассуждения попадают в ответ, а `low` ускоряет первый токен.
- **Контекст:** сократил с ~8000 до ~6000 символов. Узкое место — 8 000 токенов в минуту: с длинной историей выходит всего 2–3 запроса в минуту. По дневному лимиту получается примерно 70+ запросов, для проверки должно хватить.
- **Ошибка 429:** берём из заголовка `retry-after`, через сколько секунд можно повторить, и показываем «Try again in N s».

**Что стоит иметь в виду:**
- На странице лимитов две вкладки, Free и Developer. Обычный пересказ страницы вернул только лимиты Developer, поэтому значения для Free я достал из исходного кода страницы.
- Как именно рассуждения передаются при стриминге, в документации не описано. Мы их отключаем, но парсер всё равно должен пропускать незнакомые поля.

    let id: UUID
    var title: String

enum MessageRole: String, Sendable { case user, assistant }

/// user:      pending → sent
/// assistant: streaming → done | cancelled | failed | interrupted
enum MessageStatus: String, Sendable {
    case pending, sent, streaming, done, cancelled, failed, interrupted
    var isRetryable: Bool { get }  // failed, interrupted, cancelled
}

enum ErrorKind: String, Sendable {
    case offline, rateLimited, unauthorized, forbidden, server, unknown
}

/// Причина ошибки ответа. Хранится в БД, чтобы плашка
/// «Try again in N s» работала и после перезапуска.
struct MessageFailure: Hashable, Sendable {
    let kind: ErrorKind
    let retryAt: Date?             // из retry-after при 429
}

struct Message: Identifiable, Hashable, Sendable {
    let id: UUID
    let chatId: UUID
    let role: MessageRole
    var text: String
    var status: MessageStatus
    var failure: MessageFailure?   // только у assistant со статусом failed
    let createdAt: Date
}

struct LLMError: Error, Equatable, Sendable {
