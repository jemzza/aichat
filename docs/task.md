# Задача

AI-чат для iPhone в духе ChatGPT. Тестовое задание; оценивают и само
приложение, и то, как ведётся работа с AI (план, правила, логи, коммиты).

## Обязательные требования

- [ ] Ответ AI появляется по мере генерации (стриминг), есть кнопка «Стоп».
- [ ] Несколько чатов; история сохраняется после перезапуска.
- [ ] Состояния: загрузка, ошибка (нет сети, кончился лимит API) с кнопкой
      «Повторить», пустой экран.
- [ ] Интерфейс в духе iOS, светлая и тёмная тема.
- [ ] Минимум iOS 18; работает и на iOS 18, и на последней iOS.
- [ ] XcodeGen (`project.yml`); `Build.command` двойным кликом генерирует и
      собирает проект под симулятор.
- [ ] Зависимости только через SPM.
- [ ] Облачный AI-API; ключ в проекте в обфусцированном виде; приложение
      работает сразу после сборки без настроек; у ключа хватает лимита на проверку.
- [ ] Архив с `.git`, `docs/`, `CLAUDE.md`, `ai-logs/`, README по шаблону.

## По желанию (только после того, как готово обязательное)

- [ ] Офлайн-режим на Apple Foundation Models (iOS 26+).
- [ ] Версия для Mac (Mac Catalyst).
- [ ] Фото во вложении.
- [ ] Русская локализация интерфейса.
- [ ] Голос: озвучка ответов и диктовка (см. «Голос (бонус)»).
- [ ] Папки для чатов (см. «Папки (бонус)»).

## Модель данных

Все модели — `struct`/`enum`, `Sendable`, `Hashable`, в `Domain/Models/`.

- `Chat`: `id` (UUID), `title`, `createdAt`, `updatedAt` (= время последнего
  сообщения; обновляет репозиторий). В БД появляется только с первым сообщением.
- `Message`: `id` (UUID), `chatId` (FK, `ON DELETE CASCADE`), `role`
  (`user`/`assistant`), `text`, `status`, `failure: MessageFailure?`, `createdAt`.
  Сортировка — `ORDER BY createdAt, rowid` (время может совпасть).
- `MessageStatus`, два автомата:
  - **user:** `pending` (нет сети) → `sent` (атомарно, `claimPending`).
  - **assistant:** `streaming` → `done` | `cancelled` | `failed` | `interrupted`.
    Повтор (`failed`/`interrupted`/`cancelled`/`done` → `streaming`) переиспользует
    то же сообщение: атомарно (`claimRetry`) очищает `text` и `failure`; если ответ
    уже `streaming` — повтор отклоняется (защита от двойного «Retry»: первый
    `claimRetry` переводит ответ в `streaming`, второй получает `false`).
    `done` — это перегенерация; UI предлагает её только для последнего ответа
    в чате, иначе следующие сообщения опирались бы на текст, которого уже нет.
- `MessageFailure`: `kind: ErrorKind`, `retryAt: Date?` (из `retry-after` при 429).
  Хранится в БД (две колонки), чтобы «Try again in N s» была верной и после
  перезапуска. Есть только у ответа ассистента со статусом `failed`.
- `ErrorKind`: `offline`, `rateLimited` (429), `unauthorized` (401 или нет ключа),
  `forbidden` (403, например регион), `server` (5xx), `unknown`.
- `LLMError`: `kind: ErrorKind`, `retryAfter: Duration?` — то, что бросает `LLMProvider`.
- Ошибки репозитория: `MessageNotFound(id)`, `ChatNotFound(id)`.

## Протоколы (`Domain/Protocols/`)

- `ChatRepository` — наблюдение (`observeChats`, `observeMessages`: первое
  значение сразу, дальше при каждом изменении), `insertChat(_:firstMessage:)`,
  `renameChat`, `deleteChat` (идемпотентно), `insertMessage`, `updateMessage`
  (нет сообщения → `MessageNotFound`), `history(chatId:before:limit:)`,
  `pendingMessages`, `claimPending(messageId:reply:) -> Bool`,
  `claimRetry(assistantMessageId:) -> Bool`, `markStreamingAsInterrupted`.
- `LLMProvider` — `displayName: LocalizedStringResource`,
  `streamReply(to: [LLMMessage]) -> AsyncThrowingStream<String, Error>`;
  отмена `Task` потребителя прерывает запрос, а цикл `for try await` при этом
  заканчивается **без ошибки** — «Stop» определяется по `Task.isCancelled`.
- `ConnectivityMonitoring` — `isOnline`, `updates() -> AsyncStream<Bool>`
  (текущее значение сразу, дальше только изменения; поток на подписчика).
- `ChatSession` — то, что экранам нужно от `ChatService` сверх чтения из
  репозитория: `draftUpdates(chatId:) -> AsyncStream<StreamingDraft?>` (живой
  черновик), `send(_:inChat:) -> UUID` (`nil` — новый чат), `stopGenerating`,
  `retry(assistantMessageId:inChat:)`, `deleteChat`. `@MainActor`.
- `BackgroundTaskScheduling` — `beginTask(expiration:)` / `endTask(_:)`
  (обёртка над `beginBackgroundTask`).

## Маппинг ошибок

- `URLError` → `offline` только для `notConnectedToInternet`,
  `networkConnectionLost`, `dataNotAllowed`, `timedOut`, `cannotFindHost`,
  `cannotConnectToHost`; прочие `URLError` → `unknown`.
- `CancellationError` и `URLError.cancelled` — не ошибка, а «Стоп» → `cancelled`.
- HTTP ≠ 200: дочитать тело (до 4 KB), маппить по коду: 401 → `unauthorized`,
  403 → `forbidden`, 429 → `rateLimited` + `retry-after`, 5xx → `server`;
  прочие коды — по `type`/`code` из тела, иначе `unknown`.
- Пустой ключ → `unauthorized` без запроса в сеть.
- Соединение закрылось без `data: [DONE]` → `unknown` (ответ обрезан, а не готов).
- Ошибка внутри SSE при HTTP 200 (`data: {"error": …}`) → по полю `type`/`code`,
  иначе `server`.
- Тексты ошибок не содержат ключ, URL с параметрами и сырой ответ сервера.

## Offline-first: поведение

1. Отправка: сообщение пользователя сразу пишется в БД. Есть сеть — в одной
   транзакции user → `sent` и создаётся ответ ассистента `streaming`; нет —
   статус `pending`, в UI «Will send when online». Первое сообщение нового
   чата пишется вместе с самим чатом.
2. Outbox: при появлении сети, при запуске и при возврате в foreground
   `pending` отправляются по очереди. Переход `pending` → `sent` атомарный
   (транзакция с проверкой статуса), поэтому повторные события сети не дают
   двойной отправки.
3. Стриминг: текст копится в памяти и идёт в UI через черновик; в БД — не
   чаще ~2 раз в секунду и в конце.
4. «Стоп» → статус `cancelled`, частичный текст остаётся.
5. Запуск приложения: `streaming` → `interrupted` с кнопкой «Retry».
   Повторное нажатие «Retry» во время генерации ничего не делает (`claimRetry` → `false`).
6. На iOS 26 с доступной системной моделью без сети можно ответить офлайн
   по кнопке (см. «Решения»).
7. Удаление чата во время стриминга отменяет его `Task`; сообщения удаляются
   каскадом. Запоздавшая запись ответа получает `MessageNotFound`, `ChatService`
   её глотает.
8. «Загрузка» в UI = ожидание первого токена (индикатор «печатает…»).

## UI-референс

Ориентир — мобильное приложение Claude по **структуре и ощущению**: спокойный,
«бумажный», много воздуха. **Без** его логотипа, названия и фирменного цвета —
свой акцент и свои иконки на SF Symbols. Скриншоты референса в репозиторий не
кладём (на них чужие данные).

Интерфейс на английском; все строки ниже — ключи String Catalog
(`Localizable.xcstrings`), в коде не хардкодятся.

### Цвета и типографика

- Тёплый фон вместо чисто белого/чёрного: светлая тема — слегка кремовый,
  тёмная — тёплый тёмно-серый.
- Цвета `Background`, `Surface`, `Accent` — в `Assets.xcassets` с вариантами
  Light/Dark, в коде только через них (и системные `.primary`/`.secondary`).
- Текст ответов ассистента — шрифт с засечками (`.fontDesign(.serif)`,
  системный New York); остальной интерфейс — SF Pro. Dynamic Type везде.

### Навигация

- **iPhone:** один экран чата; список чатов — боковая панель, выезжает слева
  (кнопка в левом верхнем углу или свайп от края), основной экран сдвигается
  и затемняется. **iPad/Mac:** `NavigationSplitView`.
- **Сайдбар:** кнопка «New chat», поиск по названиям чатов,
  раздел «Recents», сгруппированный по дате (Today / Yesterday /
  Previous 7 days / Older). Долгое нажатие — контекстное меню
  «Rename» / «Delete».
- **Верхняя панель:** слева кнопка сайдбара; по центру название чата
  (нажатие — переименовать), под ним мелко текущая модель
  («Groq · <model>» / «Offline, on device»).

### Сообщения

- **Ответ ассистента** — без пузыря, на всю ширину, Markdown: заголовки,
  списки, жирный, inline-код; блоки кода — в отдельной карточке `Surface`
  с моноширинным шрифтом и кнопкой «Copy».
- **Сообщение пользователя** — справа, скруглённый пузырь цвета `Surface`,
  максимум ~80% ширины.
- Под завершённым ответом — ряд маленьких иконок: копировать и справа от неё
  «перегенерировать» (`arrow.clockwise`, только у последнего ответа в чате).
  Во время генерации — небольшой анимированный индикатор под текстом.
- **Ошибка** — спокойная плашка под сообщением: иконка, понятный текст,
  кнопка «Retry»; для 429 — «Try again in N s». Без красных алертов на весь экран.

### Поле ввода

- Внизу карточка со скруглёнными углами и тонкой обводкой: сверху
  многострочное поле (растёт до ~6 строк, плейсхолдер «Message…»), снизу ряд кнопок: слева «+» (фото — только если
  сделаем 6.3, иначе кнопки нет), справа круглая кнопка `Accent` со стрелкой
  вверх; во время генерации — квадрат «Stop». Неактивна при пустом тексте.
- Кнопка «вниз» над полем ввода, если пользователь проскроллил вверх.

### Пустой экран

- По центру приветствие по времени суток: «Good morning» / «Good afternoon» /
  «Good evening», под ним
  3–4 подсказки-чипа; нажатие сразу отправляет запрос.

### Детали

- Haptic на отправку и стоп (`.sensoryFeedback`, iOS 17+).
- Плавное появление текста при стриминге.
- Автоскролл только если пользователь внизу.
- Баннер «No connection» под верхней панелью, ненавязчивый.

## Голос (бонус)

Всё на устройстве: без сети, без сторонних зависимостей, ничего не уходит на сервер.

- **Озвучка ответов.** Под ответом (`done`/`cancelled` с текстом) — иконка
  «Read aloud» ↔ «Stop reading». `AVSpeechSynthesizer`, язык голоса — по
  `NLLanguageRecognizer`. Перед чтением Markdown убирается: блоки кода не
  читаются, заголовки и пункты списков — отдельные фразы, ссылки — только
  текст. Одновременно читается не больше одного ответа; новое чтение
  прерывает предыдущее. Учитываются системные настройки «Устного контента».
- **Диктовка.** Кнопка микрофона в поле ввода: речь распознаётся в текст
  прямо в поле, пользователь правит и отправляет сам. Аудио не сохраняется,
  голосовых сообщений нет. Во время диктовки озвучка останавливается.
- **Распознавание.** iOS 26 — `SpeechAnalyzer` + `SpeechTranscriber`;
  iOS 18 — `SFSpeechRecognizer` с on-device распознаванием, если язык его
  поддерживает. Нет разрешения на микрофон/распознавание или язык не
  поддерживается офлайн — понятное сообщение, кнопка неактивна.

## Папки (бонус)

Решения — таблица «Решения» (строки «Папки: …»).

- **Модель.** `Folder`: `id` (UUID), `name`, `position` (ручной порядок),
  `createdAt`. У `Chat` — `folderId: UUID?`. Папки одного уровня, чат —
  максимум в одной папке.
- **БД.** Миграция v2: таблица `folder`; колонка `chat.folderId` с FK на
  `folder.id` и `ON DELETE SET NULL`. Миграция v1 → v2 не трогает
  существующие чаты и сообщения — все они оказываются в «Recents».
- **Удаление папки** не удаляет чаты — они возвращаются в «Recents».
- **Порядок.** Папки — по `position` (меняет пользователь), чаты внутри
  папки — по `updatedAt`, новые сверху. «Recents» — как раньше, с
  группировкой по дате.
- **Наблюдение.** Одна подписка на весь сайдбар: `SidebarSnapshot` (папки
  по порядку, у каждой её чаты, плюс чаты без папки). Поиск фильтрует и папки,
  и «Recents».
- **Перенос чата.** Перетаскивание (`.draggable` / `.dropDestination`,
  `Transferable` со своим `UTType`, объявленным в `project.yml`) и всегда —
  пункт «Move to folder» в контекстном меню чата (доступность). Дроп с
  неизвестным или уже несуществующим ID игнорируется.
- **Управление папками.** «New folder», контекстное меню папки
  «Rename» / «Delete», изменение порядка папок.

## Известные риски

- Groq может быть недоступен из некоторых регионов (403) — проверить в шаге 2.0,
  описать в README.
- Foundation Models на симуляторе работает, только если на Mac включён Apple
  Intelligence; поддержка языков ограничена — проверить до начала 6.1.
- iOS 26 с SDK 26 автоматически применяет Liquid Glass к навбарам/тулбарам —
  свой фон у поля ввода выглядит по-разному на 18 и 26. `.glassEffect` и
  другие API iOS 26 — только за `#available`.
- Рантайм симулятора iOS 18 не входит в Xcode 26 — скачать заранее (шаг 0.1).
- Свой сайдбар со свайпом от края может конфликтовать с системным жестом
  «назад» и со скроллом — на iPhone в навигации нет push-экранов, жест «назад»
  не нужен.
- Свой блочный markdown-парсер — заметный объём работы; если не успеваем,
  откат к инлайн-разметке и запись в «Не сделано».
