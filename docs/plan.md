# План

Агент выполняет шаги по одному, после каждого — сборка, отметка `[x]`, коммит.
Время — ориентир; реалистично ~11–12 ч на обязательную часть.
Шаги с пометкой **👤** требуют действия пользователя — агент останавливается и просит.

## Журнал отклонений от плана

_Сюда записываем, что пошло не так и что решили иначе._

- Ревью плана до старта: добавлены живой черновик стриминга (исключение из
  offline-first), раздельные автоматы статусов, правило офлайн-ответа,
  маппинг ошибок, DEBUG-хуки, тесты `ChatService`, шаг выбора модели,
  `ai-logs` с первого шага; оценки пересчитаны (~6,5 ч → ~9–10 ч).
- Базовый язык интерфейса — английский (решение заказчика); русский — бонус 6.4.
- Добавлен UI-референс (структура и ощущение приложения Claude, без его
  бренда): свой сайдбар на iPhone, цвета из Assets, serif для ответов, блочный
  markdown вместо инлайнового. Раздел 4 расписан заново (~3 ч → ~5 ч), общая
  оценка ~11–12 ч.
- 0.1: отдельного `AccentColor` нет — глобальным акцентом назначен `Accent`,
  чтобы не держать два одинаковых цвета. Сгенерированный `Info.plist` в `.gitignore`.
- 0.3: заглушка `Secrets` не нужна — пользователь сгенерировал и закоммитил
  `Secrets.generated.swift` до начала работы. Пустой ключ всё равно маппится в
  `unauthorized` (шаг 2.4). Тест проверяет форму реального ключа, а не синтетику.
- 1.1 расширен по решению заказчика: протоколы `LLMProvider` и
  `ConnectivityMonitoring` (было 2.1, имя было `ConnectivityProviding`) и
  `ChatRepository` (было 1.3) объявлены сразу, вместе с фейками — чтобы UI
  можно было делать без базы и сети. 2.1 удалён, 1.3 — только GRDB-реализация,
  1.4 — подключение её к уже написанным контрактным тестам. Разбор
  launch-аргументов (`LaunchOptions`) — тоже в 1.1, подключение — в 3.5.
- Модель данных: `errorKind?` → `failure: MessageFailure?` (`kind` + `retryAt`),
  чтобы «Try again in N s» переживала перезапуск. Добавлены `claimRetry`
  (защита от двойного «Retry»), `history(…limit:)` (cancelled с текстом идёт
  в контекст), `MessageNotFound`/`ChatNotFound`, чат создаётся только вместе с
  первым сообщением. `claimPending` возвращает `Bool` вместо `Message?`.
- Язык интерфейса — английский без русских дублей в UI-референсе; все строки
  только через String Catalog.
- 2.2–2.4 (ветка `feat/llm`, параллельно с другими агентами): системный промпт
  добавляет `GroqProvider`, а не `ChatService`; поток без `[DONE]` → ошибка
  `unknown`; `retry-after` — только секунды; транспорт вынесен за протокол
  `HTTPLineStreaming` ради тестов. `GroqProvider` пока не подключён в
  `AppContainer` — это 3.2/3.5.
- Тест фейка `cancellationKeepsReceivedText` отменял по таймеру 100 мс и падал
  под параллельной нагрузкой; теперь отмена сразу после первого токена.
- UI (раздел 4) делался параллельно с данными и сетью, поэтому контракт экранов
  с `ChatService` — протокол `ChatSession` (черновик, отправка, «Stop», «Retry»,
  удаление) — появился раньше сервиса; для превью и `-mockData` —
  `PreviewChatSession`. При подключении (3.2) `ChatSession` переехал в
  `Domain/Protocols`, `ChatService` — в `Domain/Services`.
- 4.6: иконка «повторить» есть только у `cancelled`/`failed`/`interrupted`;
  перегенерировать `done` контракт `claimRetry` не позволяет.
- 4.7: таблицы markdown не поддерживаются (показываются текстом); инлайн-код
  задаётся моноширинным явно — `.fontDesign(.serif)` перебивает `.code`.
- 4.8: `ChatDependencies` получил `connectivity`; `-mockOffline` (вместе с
  `-mockData`) подключён раньше 3.5, чтобы проверить баннер.
- 4.9: при AX-размерах верхняя панель, баннер, кнопка «Send» и плавающие
  кнопки ограничены (`dynamicTypeSize(...accessibility1/2)`), текст — нет.
- 3.2: отправка всегда через `pending` + атомарный `claimPending` (тот же путь, что
  у outbox) — одна транзакция «user → `sent` + ответ `streaming`» и нет двойной
  отправки. Ответ из outbox получает `createdAt` вопроса + 1 мс, чтобы при
  нескольких `pending` подряд ответ стоял сразу за своим вопросом. Финальная
  запись после «Stop» — в отдельной `Task`: отменённая задача сама записать не
  может (асинхронная запись GRDB при отмене бросает `CancellationError`).
- 3.5: выбор реализаций — `DependencyPlan` из `LaunchOptions` (покрыт тестами);
  `-mockError` важнее `-mockSlowStream`. Репозиторий открывается асинхронно
  (`GRDBChatRepository.launch` переводит `streaming` → `interrupted`), пока —
  фон, при ошибке — экран «Couldn't open chat history».
- 3.5, проверка: на этом Mac DNS симулятора идёт через VPN-интерфейс и не
  находит `api.groq.com` (`URLError -1003` → «No internet connection»), хотя
  с хоста API доступен. Реальный ответ Groq из симулятора не проверен —
  повторить без VPN (5.1). Цепочка проверена на диске с `-mockSlowStream`,
  `-mockError 429`, перезапуском.
